## 1. Setup workflow as built (before this change)

| Step | Where | What actually happens |
|---|---|---|
| 1 | `START-TITAN.{bat,ps1,command,sh}` | Runs `setup_titan.py` with `py -3` (Windows: newest installed Python) or `python3`. |
| 2 | `setup_titan.ensure_python` | Hard exit unless 3.11–3.13. Newest-Python users (3.14+) are stopped with no alternative tried. |
| 3 | `setup_titan.ensure_adb` | `shutil.which("adb")` only. Not found → "Install Platform Tools", continue. Runs **before** the venv exists. |
| 4 | `ensure_venv` | Creates `.titan-venv`; runs `pip install -r requirements.txt` **on every launch** (offline relaunch → traceback). |
| 5 | `ensure_env` | Writes `.env` with a token only if `.env` is absent. A `.env` copied from `.env.example` (empty token) is never repaired. |
| 6 | uvicorn on 127.0.0.1:8000, browser opens | `static/index.html` |
| 7 | Browser: `GET /api/setup/session` | Loopback-only cookie. |
| 8 | Browser: `GET /api/setup/check` | PATH `adb devices -l`; naive whitespace split; `ready` = any line with state `device`. |
| 9 | Browser: `POST /api/sensors/discover` | **Different code path:** `adbutils.adb.device_list()` (talks to adb server on :5037). |
| 10 | Browser: `POST /api/sensors/capture` | `dumpsys telephony.registry` / `dumpsys wifi` per device; any exception → empty string. |

**State transitions:** none explicit. UI state = scattered booleans (`localReady`, `s.ready`) and client-side string selection. No `ready` gate requiring a capability probe.

## 6. API / CIVINTELLIGENCE boundary

- CIVINTELLIGENCE (`src/lib/pillars.ts`) **pulls** `GET /api/observations?n=50`, `/api/evidence/tail`, `/api/evidence/verify`, `/api/health` server-side with `CELL_TITAN_API_TOKEN`, from `CELL_TITAN_BASE_URL`.
- Production Titan runs with `ADB_ENABLED=false` (`render.yaml`), so it can only ever hold its boot record (production health: evidence length 1, buffer 0).
- **Gap (Phase 6):** a real user's device data lives on their local Titan (127.0.0.1). There is no submit/push path from local Titan to CIVINTELLIGENCE; `privacy.public_submission: "explicit_user_action"` is declared but unimplemented. End-to-end delivery of a genuine device observation is therefore currently impossible, not merely untested.
- **CIVINTELLIGENCE `/titan` page:** "Windows one-click launcher" links to `raw.githubusercontent.com/.../START-TITAN.bat` alone. That file does `cd %~dp0` and runs `setup_titan.py`, which will not exist next to a lone download → **launcher cannot work from that link** (P0, cross-repo; recently touched by PR #62 — coordinate before editing).

## 10. Infrastructure requirements and cost drivers

- **Layer A:** none beyond current CI.
- **Layer B, recommended first:** GitHub-hosted Linux runners with KVM + Android Emulator. Public repository → standard runner minutes are not billed (confirm against the org's current plan). Drivers: emulator boot time per API level (use AVD snapshots/caching), RAM per emulator (bounds instances per runner), concurrent-job limit of the plan.
- **Cuttlefish:** requires Linux x86_64 hosts with KVM and host packages; better device fidelity and density per host; operational cost = self-managed hosts. Evaluate after Layer B measurements.
- **Anbox Cloud:** commercial (Canonical) licensing plus hosting; justified only if Layer B/Cuttlefish cannot meet measured concurrency needs. Defer.
- **Not on Render:** the production web service (free plan) must not host emulator workloads.
